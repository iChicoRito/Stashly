# STASHLY ONBOARDING FLOW

## Overview

When Stashly is opened for the first time, the application should display a short onboarding experience before directing the user to the main Dashboard.

The onboarding should focus on helping users configure their personal vault rather than simply explaining the application.

It should remain:

* Short
* Simple
* Practical
* Skippable where appropriate
* Focused on initial vault setup

---

# ONBOARDING FLOW

```text
WELCOME
   ↓
NAME + VAULT NAME
   ↓
CHOOSE STARTER COLLECTIONS
   ↓
OPTIONAL MASTER PASSWORD
   ↓
SETUP COMPLETE
   ↓
STASHLY DASHBOARD
```

---

# PAGE 1 — WELCOME TO STASHLY

## Title

**Everything important, in one place.**

## Description

Keep your notes, files, useful links, documents, and personal information organized inside your own private vault.

## Highlights

* Stored locally on your device
* Organize with collections and tags
* Search everything quickly
* Keep important information in one place

## Visual Concept

Use a simple Stashly illustration featuring elements such as:

* Notes
* Files
* Folders
* Links
* Vault icon

The visual should introduce the concept of storing different types of personal information in one organized space.

## Primary Action

**Get Started →**

---

# PAGE 2 — MAKE IT YOURS

## Title

**Make Stashly yours**

## Description

Tell us a little about how you want your personal vault to be set up.

---

## User Name

### Label

**What should we call you?**

### Input

```text
Name

[ Mark Adrianne                     ]
```

The user's name is required.

It can later be used for personalized messages around the application.

### Example

```text
Good morning, Mark.

Welcome back, Mark.
```

---

## Vault Name

### Label

**Name your vault**

### Input

```text
Vault Name

[ Mark's Stash                      ]
```

The vault name is optional.

If the user leaves the field empty, Stashly can automatically generate a vault name using the user's name.

### Example

```text
Mark's Stash
```

The vault can be renamed later through:

```text
Settings → Vault
```

```text
← Back                         Continue →
```

# PAGE 3 — WHAT ARE YOU KEEPING?

## Title

**What will you keep in Stashly?**

## Description

Choose anything that applies. Stashly can prepare some starter collections for you.

---

## Categories

```text
☑ Personal Documents

☑ Projects

☐ Work

☑ Learning & References

☐ Important Records

☐ Images & Media
```

Users can select multiple categories.

There should be no required minimum number of selections.

---

## Starter Collections

Selected categories can automatically become starter collections inside the user's vault.

### Example Selection

```text
Personal Documents
Projects
Learning & References
```

### Generated Collections

```text

Projects

```

These collections are only starting points.

Users can later:

* Rename them
* Delete them

* Create additional collections

# PAGE 4 — PROTECT YOUR STASH

## Title

**Keep your vault private**

## Description

Add a Master Password to lock Stashly and help protect your personal information when you're away from your device.

Setting a Master Password during onboarding is optional.

---

## Master Password

```text
Master Password

[ •••••••••••••••              👁 ]
```

## Confirm Password

```text
Confirm Password

[ •••••••••••••••              👁 ]
```

The user should be able to show or hide the password while typing.

---

## Skip Option

Provide a clearly visible:

**Skip for now**

Display a short explanation:

> You can enable Vault Lock anytime from Settings → Security.

---

## Storage Information

Stashly should automatically use its default local application storage.

Display a simple indicator:

```text
Storage

● This Device
```

Users should not be required to select folders, directories, database locations, or storage paths during onboarding.

Advanced storage-related options can be placed inside Settings later.

# ONBOARDING DATA TO SAVE

After onboarding, Stashly should save the user's initial configuration locally.

| Data                          | Required  |
| ----------------------------- | --------- |
| User Name                     | Yes       |
| Vault Name                    | No        |
| Selected Starter Collections  | No        |
| Master Password Configuration | No        |
| Onboarding Completed          | Yes       |
| Local Storage Configuration   | Automatic |

---

# ONBOARDING STATE

Stashly should determine whether onboarding needs to appear when the application launches.

## First Launch

```text
Application Opens
      ↓
Onboarding Completed?
      ↓
     No
      ↓
Show Onboarding
```

## Returning User

```text
Application Opens
      ↓
Onboarding Completed?
      ↓
     Yes
      ↓
Open Dashboard
```

Once onboarding is completed, it should not automatically appear again.

---

# ONBOARDING PRINCIPLES

The onboarding experience should:

* Be quick to complete
* Configure the user's personal vault
* Avoid unnecessary technical settings
* Allow optional steps to be skipped
* Keep local storage as the default
* Introduce security without forcing it
* Give users immediate access to Stashly
* Avoid overwhelming first-time users

---

# DO NOT INCLUDE DURING ONBOARDING

The following options should remain outside the initial setup process:

* Theme configuration
* Backup configuration
* Import and export settings
* Keyboard shortcuts
* Search tutorials
* Storage path configuration
* Advanced security configuration
* Technical database settings
* Cloud synchronization
* Advanced application preferences

These features can be configured later through Stashly Settings.

# CORE ONBOARDING GOAL

The onboarding should answer four simple questions:

```text
Who owns this vault?
        ↓
What is the vault called?
        ↓
What does the user want to organize?
        ↓
Does the user want to protect it with a password?
```

Once those questions are answered, the user should immediately enter Stashly and begin organizing their personal information.
